Cafeteria menus,
in Discord, before you're hungry.

A Discord bot that posts the Uzumasa and Kameoka campus cafeteria menus to subscribed servers every weekday at 6:00 AM JST — with student prices, allergens, dish ratings, and a notice when the cafeteria is shut.

View the source whatsforlunch.lol

What it does

Posts every weekday morning

A scheduled run at 6:00 AM JST groups subscribers by campus and posts each campus's menu once, mentioning only the people who asked to be pinged.

Two campuses, separately

A server can follow Uzumasa, Kameoka, or both — in the same channel or different ones. Each gets its own notify-menu-<campus> role, created automatically.

Prices that are actually right

Student prices are derived from the scanned menu: the Uzumasa discount campaign tiers, and a flat ¥400 for halal. Kameoka's printed price is already the student price.

Dish ratings

Rate today's dishes 1–5 stars from a button on the menu post. Future menus show the average beside the dish, so the good ones are easy to spot.

Closed days say so

During a closure, /nextmenu explains that nothing is being served and shows the reopening date instead of silently jumping to the next menu.

Failures are visible

A local dashboard separates "no menu today" from "a menu that reached nobody", and the admin gets a DM when a scrape is mislabelled or a price is missing.

Commands

Every command asks which campus first, then does the thing.

CommandWhoWhat it does
/subscribeAdminsPosts that campus's menu in this channel each morning. Creates the ping role if it's missing.
/unsubscribeAdminsStops the daily posts for that campus. Your settings are kept and can be switched back on any time.
/notifyEveryoneToggles the campus ping role on yourself — be told when the menu lands, without reading every post.
/statusEveryoneWhether this server follows the chosen campus, and which channel receives it.
/previewEveryoneToday's menu, privately, on demand.
/nextmenuEveryoneThe next day a menu exists for — or the reopening date, if the cafeteria is closed.

How it works

The weekly cafeteria PDF is picked up and parsed into structured dishes — day, category, price, calories, allergens — by an n8n workflow.

Rows land in a PostgreSQL table the bot reads. The bot never writes menus; it only reads them and records what it delivered.

A scheduled run posts each campus's menu to its subscribers, skips anyone already served that day, and reports the outcome — including to Uptime Kuma.

Self-hosted, by design

There is no public instance to invite. The bot runs as a systemd service beside the database, reads its whole configuration from a .env, and deploys with systemctl. Setup, environment variables and the admin dashboard are documented in the repository.
